# Refine a Brand-Specific Skill

**Outcome:** improve an active company-owned skill from feedback without silently changing the brand or overfitting one example.

**Quality loop:** use the active skill on representative work → review the output → capture specific feedback and examples → identify the underlying guidance change → approve and apply a narrow refinement → retest representative and unaffected cases. Repeating this loop should improve quality without turning every isolated preference into a brand rule.

1. Inspect the exact user feedback, affected output, current `SKILL.md`, canonical brand records, relevant examples/dislikes, and prior version/history if available.
2. Explain what the feedback may mean at the design-principle level. Distinguish a local execution problem from a durable brand rule.
3. Identify the likely cause in the current skill: missing guidance, ambiguous wording, excessive constraint, conflicting rule, wrong priority, or execution failure unrelated to the skill.
4. Test whether the proposed lesson generalizes across the intended medium. One isolated preference or failure must not redefine the whole brand.
5. Propose an explicit narrow change, showing old guidance, new guidance, rationale, affected behavior, risks, and whether canonical brand truth would also need a decision.
6. Ask for approval. Casual feedback alone never authorizes an approved skill change.
7. After approval, update only the agreed guidance. Preserve useful rules, increment version information where practical, record date/approver/source, and retain a concise history entry or version-control reference.
8. Validate with representative cases, including at least one unaffected use case to check for overfitting. Log only a material refinement.
